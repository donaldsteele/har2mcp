# har2mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A cross-platform Go CLI that records a labeled browser session against a device's web UI, analyzes it into an editable spec, and generates a compilable Go MCP server that gives Claude full control of that device.

**Architecture:** There are four stages joined by two file formats:

```
record → HAR 1.2 (+ _har2mcp fields) → analyze → spec YAML → generate → Go module
```

Each stage is its own package under `internal/`. They communicate only through the `har` and `spec` types defined in Task 1. A simulated NAS (`internal/fakenas`) is the shared test target.

**Tech Stack:**
- Go 1.27 (the `go` directive is `go 1.26`)
- `github.com/chromedp/chromedp` and `github.com/chromedp/cdproto`
- `github.com/modelcontextprotocol/go-sdk`
- `go.yaml.in/yaml/v3` (fall back to `gopkg.in/yaml.v3` if that path won't resolve)
- `github.com/anthropics/anthropic-sdk-go`
- stdlib `flag` for the CLI

**Spec:** `docs/superpowers/specs/2026-11-21-har2mcp-design.md`. Read it before starting any task.

## Global Constraints

- **Module path** is `github.com/donaldsteele/har2mcp`. go.mod has `go 1.26`.
- **Toolchain:** the local toolchain is at `$HOME/.local/go/bin`. Every shell must run `export PATH=$HOME/.local/go/bin:$HOME/go/bin:$PATH`. **Python is not available**: use bash, node or Go.
- **Dependencies** are limited to the five in the Tech Stack line. Nothing else without a recorded reason.
- **Builds:** CGO_ENABLED=0 must build for windows/amd64, windows/arm64, darwin/amd64, darwin/arm64, linux/amd64 and linux/arm64.
- **Recordings** are written with mode 0600, and a warning is printed to stderr. Spec files and generated code never contain recorded passwords, cookies or tokens.
- **Nothing leaves the machine** except through `har2mcp enhance`. `enhance --dry-run` prints the exact payload and sends nothing.
- **Recording body cap:** 2 MiB (2097152 bytes) per request or response body. Above the cap the body text is dropped and `_truncated: true` is set.
- **Tool results** in generated servers are capped at 100000 bytes, then truncated with a final line `[truncated: <N> bytes total]`.
- **MCP tool names** match `^[a-z][a-z0-9_]{0,63}$` and are unique within a spec.
- **Service names** match `^[a-z][a-z0-9_]{0,31}$`.
- **Environment variables:** the prefix is `strings.ToUpper(service.name)`. The variables are:

  | Variable | Purpose |
  |---|---|
  | `<P>_URL` | service URL |
  | `<P>_USER` | username |
  | `<P>_PASSWORD` | password |
  | `<P>_INSECURE` | `1` skips TLS verification |
  | `<P>_FILES_DIR` | file root; default `~/har2mcp-files/<name>` |

- **Generated code** is gofmt-clean, passes `go vet`, and builds with `go build ./...` with no edits.
- **`custom.go`** in a generated directory is created only if missing and never overwritten.
- **The generated file sandbox:** every local path resolves inside `<P>_FILES_DIR`. A path that escapes it after `filepath.Clean` and `filepath.EvalSymlinks` (on the parent for new files) is an error.
- **Default model** for `enhance` is `claude-opus-5-5`.
- **Files and license:** Apache-2.0. Copy `LICENSE` from `github.com/donaldsteele/rocket`. `NOTICE` starts `har2mcp\nCopyright 2026 Don Steele`.
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Parallel agents (Tasks 2, 3, 4 and 7) do **not** commit. Task 5 commits their work.

## Review Focus

1. **A plain HAR exported from Chrome DevTools.** These are sanitized (no Cookie, Set-Cookie or Authorization headers), use base64 bodies and carry `_resourceType`. `analyze` must still produce a valid spec with `auth.review: true` rather than failing. *Test:* `TestAnalyzeDevToolsSanitizedHAR` (Task 3).
2. **A device with a self-signed TLS certificate.** `record --insecure` must record it, and a generated server with `<P>_INSECURE=1` must connect. *Test:* `TestE2E_TLSInsecure` (Task 5).
3. **The session expiring mid-use.** The generated server logs in again on 401/403, or when `relogin_body_contains` matches, then retries the call once. *Test:* `TestE2E_SessionExpiryRelogin` (Task 5).
4. **Odd step labels.** For example `""`, `"🔥 Reboot!!"`, `"2fa setup"`, `"type"`, `"list disks"` twice, or non-ASCII text. These must produce valid, unique MCP names and Go identifiers that compile. *Tests:* `TestToolNameSanitizing` (Task 3) and `TestGenerateCompilesOddNames` (Task 4).
5. **File paths that escape the sandbox.** For example `../../etc/passwd`, an absolute path outside the root, or a symlink pointing out. They must return an MCP error result and touch nothing. *Test:* `TestE2E_FileSandbox` (Task 5).

The fakenas HTTP API is fixed. Tasks 3, 5 and 7 rely on these exact names.

| Method + path | Request | Response |
|---|---|---|
| `GET /` | | SPA: `index.html`, `/static/app.js`, `/static/style.css`, `/static/logo.png` |
| `GET /api/nonce` | | `{"nonce":"<random hex>"}` (used only when Scramble) |
| `POST /api/login` | JSON `{"username","password"}` | 200 `{"ok":true,"data":{"token":"<csrf>"}}` + `Set-Cookie: NASSESSID=<id>; HttpOnly; Path=/`. Bad credentials: 401 `{"ok":false,"error":"bad credentials"}` |
| `POST /api.php` | JSON `{"act": …}` + header `X-Csrf-Token` + cookie | No or expired session: 401 `{"ok":false,"error":"not logged in"}`. Bad CSRF: 403 `{"ok":false,"error":"bad token"}` |
| `POST /api/upload` | multipart: field `path` (folder), file part `file` | `{"ok":true}`. Same auth rules |
| `GET /api/download?path=<nas path>` | | `Content-Disposition: attachment; filename="<base>"`, `application/octet-stream`. Same auth rules |

`act` values:
- `getdisklist` returns `{"ok":true,"data":[{"id":"sda","model":"WD Red 4TB","size_gb":4000,"health":"good"},{"id":"sdb","model":"WD Red 4TB","size_gb":4000,"health":"good"}]}`
- `getsysinfo` returns `{"ok":true,"data":{"model":"F4-424","version":"TOS 6.0.1","uptime_s":<n>}}`
- `getsharelist` returns `{"ok":true,"data":["public"]}` initially
- `addshare` takes `{"name":…}`
- `delshare` takes `{"name":…}`
- `reboot` returns `{"ok":true}` and sets a flag

SPA element ids:
- login: `#username`, `#password`, `#login` (submit)
- buttons: `#btn-disks`, `#btn-sysinfo`, `#btn-shares`
- add share: `#share-name`, `#btn-add-share`

`client_gen.go`:

```go
type Client struct{ /* base URL, http.Client with cookie jar, tokens, mutex */ }
func NewClientFromEnv() (*Client, error)
func (c *Client) Do(ctx context.Context, method, path string, query url.Values, bodyType string, body map[string]any) (status int, respBody []byte, header http.Header, err error)
```

It logs in lazily, logs in again and retries once on `ReloginOn` statuses or `ReloginBodyContains`, injects tokens per `Session.Tokens`, and honors `<P>_INSECURE`.

The Claude Code registration line in the README:

```
claude mcp add --transport stdio --env <P>_URL=… --env <P>_USER=… --env <P>_PASSWORD=… <name> -- /path/to/<name>-mcp
```

Handlers merge fixed `Body`/`Query` with inputs. Dotted `Field` paths set nested keys. Each handler returns the response as `mcp.TextContent`, capped at 100000 bytes. A non-2xx status gives `IsError: true` with the status and the first 2000 bytes of the body. File tools return `{"path","bytes","content_type"}` JSON, never file contents.
